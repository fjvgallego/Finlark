# Finlark v1.0 requirements

Status: **Accepted** (2026-10-28) · Platform: iPhone, iOS 26+ · Languages: English, Spanish

Terms follow the [glossary](../glossary.md). Requirement IDs are stable (see [docs conventions](../README.md#conventions)).

## 1. Scope summary

v1.0 is a manual-entry personal finance tracker for iPhone with:

- One account with a balance, expense and income transactions, and editable flat categories.
- Recurring templates with **confirm-to-post** pending items.
- A **Monthly Plan** (planned amount per category) with a pace **projection**.
- **Bill splitting** (Equal, Exact amounts, By item) for expenses the user paid, with per-ticket repayment tracking and
  *Settle all* per person.
- A Home overview, local notifications (recurring due, IOU reminders), optional app lock, and iCloud sync.

v1.0 has **no** AI, App Intents, widgets, bank sync, CSV, payee field, multi-account UI or FX (see §5).

## 2. Platform and technical constraints

| # | Constraint |
|---|---|
| C-1 | iPhone only, minimum iOS 26. APIs newer than iOS 26 are gated with `#available`. |
| C-2 | SwiftUI, SwiftData, CloudKit (private database), Swift Charts, LocalAuthentication, UserNotifications. No third-party SDKs that collect data. |
| C-3 | The data model must be CloudKit-compatible from day one: no unique constraints, all properties optional or defaulted, all relationships optional. |
| C-4 | The data model supports multiple accounts and per-transaction currency codes even though v1 UI exposes one account and one currency. |
| C-5 | No network access other than CloudKit. No backend. |

## 3. Functional requirements

### 3.1 Onboarding (ONB)

#### ONB-001 Choose home currency
As a new user, I want to choose my home currency so amounts show the way I expect.
- Given I open Finlark for the first time, when the currency step appears, then it defaults to my device locale's
  currency, and I can pick any ISO 4217 currency from a searchable list.

#### ONB-002 Set starting balance
As a new user, I want to enter how much money I have now so my balance is right from the start.
- Given I'm on the starting-balance step, when I enter an amount (zero and negative allowed) and continue, then a
  default account is created with that starting balance in my home currency.

#### ONB-003 Optional app lock
As a new user, I want to choose whether to protect Finlark with Face ID or my passcode.
- Given I'm on the app-lock step, when I enable it, then app lock is turned on (see SEC-001). When I skip, then it stays
  off and can be enabled later in Settings.

#### ONB-004 Default categories
As a new user, I want sensible categories ready to use.
- Given onboarding finishes, then the default expense and income categories (Appendix A) exist, localized to the app
  language.
- Default data (account, categories) must not be duplicated when the same iCloud data syncs to another install (see
  A-12).

#### ONB-005 Restore existing data
As a returning user on a new iPhone, I don't want to repeat onboarding when my data is already in iCloud.
- Given my iCloud account already contains Finlark data, when I open the app for the first time, then onboarding is
  skipped once the data is available, and no duplicate default account or categories are created.
- Given iCloud data is still downloading, then I see a clear "Restoring from iCloud…" state with an option to continue
  as a new user.

### 3.2 Account and balance (ACC)

#### ACC-001 Balance
As a user, I want to see my current balance.
- Balance = starting balance + Σ income − Σ expenses (**full amount paid**, including split expenses) + Σ repayments.
- Given a €1,000 balance, when I add a €120 split expense, then the balance is €880. When one friend repays €30, then
  it is €910.
- Pending recurring items don't affect the balance.

#### ACC-002 Edit account
As a user, I want to rename my account and correct its starting balance.
- Given I change the starting balance in Settings, then the current balance is recalculated, and no transactions are
  created or changed.

### 3.3 Transactions (TRX)

#### TRX-001 Add expense
As a user, I want to log an expense quickly.
- Fields: amount (required, > 0), date (defaults to today, can be past or future), category (required, expense
  categories only), note (optional).
- The transaction stores the home currency code.
- Given I save, then the balance decreases by the amount and month spending increases by the amount (or by my share
  if split; see SPL).
- The add screen opens from a prominent button on Home and History, with the amount field focused.

#### TRX-002 Add income
As a user, I want to log income (salary, refunds…).
- Same fields as TRX-001, with income categories only.
- Given I save, then the balance increases by the amount, and spending doesn't change.

#### TRX-003 Edit transaction
As a user, I want to fix a transaction I entered wrong.
- Given I edit any field and save, then the balance, spending, plan and projections reflect the change.
- Switching type (expense ↔ income) requires choosing a category of the new type. A split expense can't be switched to
  income.

#### TRX-004 Delete transaction
As a user, I want to delete a transaction.
- Given I delete a non-split transaction and confirm, then it's removed and all totals update.
- Split transactions follow SPL-011.

#### TRX-005 History
As a user, I want to browse past transactions.
- Transactions are grouped by day, newest first, showing amount, category icon/name, note and a split indicator. For split
  expenses, both the amount paid and my share are shown.
- Filter by month, type (expense/income) and category. Search in notes.
- Each month shows totals: income, spending.

#### TRX-006 Transaction detail
As a user, I want to see everything about a transaction.
- Shows all fields. For split expenses, it embeds the split detail (SPL-005).

### 3.4 Categories (CAT)

#### CAT-001 Create category
As a user, I want my own categories.
- Fields: name (required, unique among active categories of the same type, case-insensitive), type (expense/income),
  SF Symbol icon, color.

#### CAT-002 Edit category
- Given I rename or restyle a category, then all its transactions show the new name, icon and color.
- A category's type can't be changed once it has transactions.

#### CAT-003 Archive category
As a user, I want to hide categories I no longer use without losing history.
- Given I archive a category, then it disappears from pickers and from the Plan editor, and its past transactions and
  stats keep showing it.
- Archived categories can be unarchived. Categories can't be deleted in v1 (archive instead).
- Archiving a category that is used by a recurring template asks me to pick a replacement category for that template.

### 3.5 Recurring (REC)

#### REC-001 Create recurring template
As a user, I want to define repeating transactions such as rent, subscriptions or salary.
- Fields: type, amount, category, note, frequency (weekly, monthly, yearly), start date, optional end date.
- Can be created from scratch or from an existing transaction ("Make recurring").
- Monthly items on the 29th–31st fall on the last day of shorter months.

#### REC-002 Pending items
As a user, I want due recurring transactions to wait for my confirmation.
- Given a template's occurrence date is today or earlier and it hasn't been confirmed or skipped, then it appears as
  a pending item on Home (HOM-005) and in the Recurring list.
- Pending items don't affect balance or spending.
- Missed occurrences accumulate (e.g. 2 pending months if the app wasn't opened).
- Pending items must not be duplicated when data syncs between installs (see A-12).

#### REC-003 Confirm pending item
- Given I confirm a pending item (optionally editing amount, date or note first), then a transaction is created and
  the item stops being pending.

#### REC-004 Skip pending item
- Given I skip a pending item, then no transaction is created and the occurrence is marked skipped.

#### REC-005 Manage templates
As a user, I want to edit, pause or delete recurring templates.
- Edits apply to future occurrences only. Past transactions are untouched.
- Paused templates generate no pending items until resumed.
- Deleting a template keeps the transactions it already created.

### 3.6 Monthly Plan (PLN)

#### PLN-001 Set planned amounts
As a user, I want to set how much I expect to spend per category each month (e.g. Fuel €100, Leisure €200).
- I can set, change or clear a planned amount for any active expense category.
- The plan carries over to following months. Changes apply from the current month onward. Past months keep the
  amounts they had (see A-08).

#### PLN-002 Plan overview
As a user, I want to see how each category is doing against its plan.
- For the current calendar month, each planned category shows planned, spent (my **spending**, i.e. my share of splits),
  remaining, and projection.
- Status per category: *On track* (projection ≤ planned), *At risk* (projection > planned and spent ≤ planned),
  *Over* (spent > planned). Status is never conveyed by color alone.
- Spending in categories without a plan is shown as "Unplanned".
- Totals: total planned vs total spent vs total projected.
- I can browse previous months (read-only plan vs actual).

#### PLN-003 Projection
As a user, I want to know early whether I'll stay within plan.
- Projection(category) = spent so far + (variable spending so far ÷ elapsed days × remaining days) + pending and
  upcoming recurring expenses for that category still due this month. "Variable spending" excludes spending that
  came from recurring templates.
- During the first 3 days of a month the pace part is hidden. Only spent + recurring due is shown (see A-09).
- Projections are computed for the current month only.

### 3.7 People (PPL)

#### PPL-001 Add person
As a user, I want to add friends I split expenses with.
- Fields: name (required). Optionally pick a contact with the system contact picker to prefill the name (no Contacts
  permission requested).
- People can also be created inline while creating a split.

#### PPL-002 People list
- Lists people with the total each currently owes me, people with open debts first.
- Shows the overall "Owed to you" total.

#### PPL-003 Person detail
As a user, I want to see what a friend owes me and why.
- Shows the total owed, open shares (ticket, date, share, paid so far, remaining) and settled history.
- Actions: *Settle all* (SPL-008), *Share reminder* (NTF-003).

#### PPL-004 Edit or remove person
- I can rename a person.
- A person with open shares can't be deleted. A person without open shares can be archived (hidden from pickers,
  history kept).

### 3.8 Splits (SPL)

v1 only supports splits of expenses **the user paid** ("they owe me").

#### SPL-001 Create split
As a user, I want to split an expense I paid with friends.
- When adding or editing an expense, I can turn on "Split" and choose participants. The user is always a participant,
  and the user's share may be €0 (paying entirely for others).
- The transaction amount is the full amount paid. The category applies to my share.
- Given a €120 Dining split equally among me + 3 friends, then the balance decreases by €120, Dining spending
  increases by €30, and "Owed to you" increases by €90.

#### SPL-002 Equal mode
- Amount ÷ number of participants, rounded to the currency's minor unit. Any remainder goes to the user's share
  (A-03).
- Given €100 among 3, then friends owe €33.33 each and my share is €33.34.

#### SPL-003 Exact amounts mode
- I enter each participant's share, and the shares must add up to the total before I can save.
- The UI shows the remaining unassigned amount live.

#### SPL-004 By item mode
As a user, I want to split a dinner by what each person had.
- I add items (name optional, amount required), and each item is assigned to one or more participants. A shared item is
  divided equally among its assignees (remainder to the user if assigned, otherwise to the first assignee).
- The total is the sum of items. Unassigned items count as the user's.
- Tips, service charges or discounts aren't modelled separately in v1; they can be added as an item assigned to
  everyone.
- Given Ana: pizza €12, me: pasta €10, wine €18 shared by both, then Ana owes €21 and my share is €19.

#### SPL-005 Split detail
- Shows the total paid, my share, mode, and for each debtor: share, paid so far, remaining, status (*Pending*,
  *Partially paid X of Y*, *Paid*).

#### SPL-006 Mark debtor paid
As a user, I want to record that a friend paid me back their share.
- Given Marta is pending €30 on a split, when I mark her as paid, then her status is *Paid*, the balance increases by
  €30, spending doesn't change, and "Owed to you" decreases by €30.
- The repayment date defaults to today and can be changed.

#### SPL-007 Partial repayment
- Given Luis owes €30 on a split, when I record €20, then his status is *Partially paid 20 of 30*, the balance increases by
  €20, and €10 remains owed.
- A repayment can't exceed the remaining amount for that share (A-04).

#### SPL-008 Settle all
As a user, I want to settle everything a friend owes me at once ("I'll send you €55 for both dinners").
- Given Marta has open shares of €30 and €25, when I tap *Settle all* on her person screen and confirm, then both shares
  become *Paid*, each gets a repayment for its remaining amount (same date), and the balance increases by €55.

#### SPL-009 Edit or undo repayment
- I can edit the amount or date of a repayment, or delete it, from the split detail. Totals update accordingly.

#### SPL-010 Edit a split
- Mode, participants, shares and items can be edited.
- A participant's share can't be reduced below what they have already repaid, and a participant with repayments can't
  be removed (A-05).

#### SPL-011 Delete a split expense
- Given a split expense has repayments, when I delete it, then I'm warned that its repayments will also be deleted,
  and on confirming, the transaction, shares and repayments are removed and the balance is recalculated (A-06).

### 3.9 Home (HOM)

#### HOM-001 Balance card
- Shows the current balance (ACC-001).

#### HOM-002 Month summary
- Current month: income, spending, and the difference, with a simple chart (Swift Charts) of spending by category.

#### HOM-003 Plan card
- Total spent vs total planned with projection and status. Tapping opens the Plan overview.
- If no plan is set, it invites the user to create one.

#### HOM-004 Owed to you card
- Total owed to the user and number of people. Tapping opens People. Hidden when nothing is owed.

#### HOM-005 Pending recurring
- Lists pending items with quick Confirm and Skip. Hidden when there are none.

#### HOM-006 Recent transactions
- Last 5 transactions with a link to History.

#### HOM-007 Quick add
- A prominent add button opens TRX-001 (with an option to switch to income).

### 3.10 Notifications (NTF)

#### NTF-001 Recurring due
- Given a recurring occurrence becomes due, then a local notification fires on its due date at 09:00 local time.
  Tapping it opens the confirm screen for that item.

#### NTF-002 IOU reminder
- Given a debtor's share on a split is still not fully paid N days after the split date (N default 7, configurable
  1–60 in Settings), then a local notification fires once for that share ("Marta still owes you €30 for Dinner at
  Casa Pepe"). Tapping it opens the person detail.

#### NTF-003 Share reminder message
As a user, I want to nudge a friend to pay me back.
- From the person detail (or the IOU notification target), *Share reminder* opens the share sheet with a localized
  message listing the open shares and total ("Hi Marta! Friendly reminder: Dinner at Casa Pepe €30, Cinema €25,
  total €55.").

#### NTF-004 Notification permission and settings
- Notification permission is requested the first time it's needed (first recurring template or first split), not
  at launch.
- Each notification type can be turned off in Settings.

### 3.11 Security and privacy (SEC)

#### SEC-001 App lock
- When enabled, the app requires Face ID / Touch ID with device passcode fallback on launch and when returning from
  background after 1 minute or more.

#### SEC-002 Privacy snapshot
- When app lock is enabled, the app-switcher snapshot is obscured (blurred or a placeholder).

#### SEC-003 Delete all data
As a user, I want to permanently remove all my Finlark data.
- From Settings, after a destructive confirmation (typing or a second confirmation step), all local data and the
  app's iCloud data are deleted, and the app returns to onboarding.

### 3.12 Sync (SYN)

#### SYN-001 iCloud sync
- When the user is signed in to iCloud, all data syncs automatically through the CloudKit private database.
  No manual action is needed.

#### SYN-002 Works without iCloud
- When iCloud is unavailable or signed out, the app works fully locally, Settings shows the sync status, and syncing
  resumes when iCloud becomes available.

#### SYN-003 Conflicts
- Concurrent edits to the same record resolve as last-writer-wins (CloudKit default). There's no conflict UI in v1 (A-11).

### 3.13 Settings (SET)

#### SET-001 Settings screen
Contains:
- Account: name, starting balance (ACC-002).
- Home currency: shown. Changeable only while there are no transactions (A-07).
- Categories management (CAT).
- Recurring templates (REC-005).
- Notifications: toggles per type, IOU reminder days (NTF-004).
- App lock toggle (SEC-001).
- iCloud sync status (SYN-002).
- Delete all data (SEC-003).
- About: version, privacy policy link, acknowledgements.

App language follows the system / per-app language setting in iOS Settings.

## 4. Non-functional requirements (NFR)

| ID | Requirement |
|---|---|
| NFR-001 | **Platform:** iPhone, iOS 26+. Portrait layout required. Landscape not required in v1. |
| NFR-002 | **Design:** follows the current iOS design language (Liquid Glass), system components and SF Symbols. Supports light and dark mode. |
| NFR-003 | **Accessibility:** Dynamic Type up to the largest accessibility sizes without truncating key info. VoiceOver labels on all interactive elements and charts (audio graph / summaries). Respects Reduce Motion. Status never conveyed by color alone. WCAG AA contrast. |
| NFR-004 | **Localization:** English and Spanish via String Catalogs, including plurals. Amounts, dates and numbers formatted with the user's locale (e.g. `1.234,56 €` in es-ES). No hard-coded user-facing strings. |
| NFR-005 | **Money correctness:** amounts stored and computed as `Decimal`, never floating point. Rounding to the currency's minor unit happens only at split-share boundaries (SPL-002/004) and for display. |
| NFR-006 | **Offline-first:** every feature works without network. CloudKit is the only network use. |
| NFR-007 | **Privacy:** no analytics, tracking or third-party data SDKs. App Privacy label "Data Not Collected". Public privacy policy URL before submission. |
| NFR-008 | **Performance:** cold launch to interactive Home < 1 s on a recent iPhone. History scrolls smoothly and Home/Plan aggregates compute in < 100 ms with 10,000 transactions. |
| NFR-009 | **Quality:** domain logic (balance, spending, split math, repayments, projection, recurrence dates) covered by automated unit tests (Swift Testing). Tests and build run in CI on every push. |
| NFR-010 | **Data model evolution:** the SwiftData schema is versioned with migration plans from v1.0 onward, and stays CloudKit-compatible (C-3). |
| NFR-011 | **Extensibility seams:** core operations (add transaction, create split, record repayment, confirm pending item) are exposed as UI-independent use cases so v2.0 App Intents and Foundation Models features can call them. |
| NFR-012 | **Reliability:** no data loss on crash or force-quit. Saves are atomic per user action. |

## 6. Assumptions to review

Defaults chosen during drafting. Confirm or change them before architecture starts.

| ID | Assumption |
|---|---|
| A-01 | Amounts are entered and shown in the home currency only. Each transaction still stores its currency code. |
| A-02 | Transactions can be dated in the future. They count toward balance and spending of their date's month. |
| A-03 | Rounding remainders in Equal mode (and shared items) go to the user's share. |
| A-04 | A repayment can't exceed the remaining amount of that share. Overpayments aren't modelled. |
| A-05 | A share can't be edited below what was already repaid, and participants with repayments can't be removed from a split. |
| A-06 | Deleting a split expense deletes its repayments too (after a warning), so the balance is recalculated as if neither existed. |
| A-07 | The home currency can only be changed while there are no transactions (until FX exists in v3.4). |
| A-08 | The Monthly Plan carries over month to month. Edits apply from the current month forward, and past months keep their values. |
| A-09 | The projection's pace part is hidden during the first 3 days of the month to avoid noisy estimates. |
| A-10 | IOU reminders fire once per share (no repeats) in v1. |
| A-11 | Sync conflicts resolve last-writer-wins with no conflict UI. |
| A-12 | Default data (account, categories) and recurring occurrences must be designed so syncing two installs doesn't create duplicates (e.g. deterministic identifiers plus dedup on import). This is an architecture topic, to be resolved in an ADR. |
| A-13 | Categories can't be deleted in v1, only archived. |
| A-14 | App lock re-locks after 1 minute in the background. |

## Appendix A: default categories

**Expense:** Groceries, Dining, Transport, Fuel, Housing, Bills & Utilities, Health, Shopping, Leisure,
Subscriptions, Travel, Other.

**Income:** Salary, Refunds, Gifts, Other income.

Names are localized (EN/ES). Icons and colors are chosen during UI design.
